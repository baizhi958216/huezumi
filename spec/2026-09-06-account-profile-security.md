# 帐号资料本地头像与密码修改

- 状态：accepted
- 负责人：待定
- 创建日期：2026-09-06
- 相关 issue / ADR：无

## 背景与问题

当前帐号页面的个人资料只允许输入头像在线地址，无法上传本地图片；帐号也没有修改密码入口。头像在线地址不经过平台素材所有权和内容校验，不能满足私有素材的帐号边界。

## 目标

- 用户可以在个人资料页面上传本地图片作为头像，并预览、保存或移除头像。
- 用户可以输入当前密码和新密码修改帐号密码。
- 头像只能引用当前用户通过私有文件接口上传的图片，不能通过资料接口写入外部 URL。
- 修改密码后撤销该用户已有会话，并为当前请求建立新的会话。

## 非目标

- 本次不实现找回密码、邮箱验证或双因素认证。
- 本次不改变通用素材上传的大小上限和存储后端。
- 本次不迁移已经保存的历史外部头像地址；历史地址仍可展示，用户下次上传或移除头像时才切换到新规则。

## 用户流程

1. 已登录用户打开个人资料页面，点击上传头像并选择本地图片。
2. 浏览器通过私有文件接口上传图片；成功后显示预览，并在保存资料时将该素材绑定为头像。
3. 用户可以移除头像，保存后回退到昵称首字；未完成保存时不改变已生效资料。
4. 用户填写当前密码、新密码和确认密码并提交。成功后当前页面保持登录，其他已有会话失效。

## 行为契约

- `PATCH /api/auth/profile` 继续修改昵称；`avatarUrl` 仅接受空字符串或当前用户的 `/api/files/<asset-id>` 图片路径。外部 `http(s)` 地址、他人素材、已删除素材和非图片素材返回 `422`。
- 头像图片使用现有 `POST /api/files` multipart 字段 `file` 上传，沿用登录用户的存储空间、媒体签名和 OSS/本地开发存储规则。
- `POST /api/auth/password` 接收 `{ currentPassword, newPassword }`。两者均为 1 至 128 个字符，新密码至少 10 个字符；当前密码错误返回 `401`，格式无效返回 `422`。
- 修改密码成功后更新密码哈希，删除该用户的全部旧 session，再通过当前响应下发新的 HttpOnly session Cookie；不返回密码或密码哈希。
- 资料和密码接口继续由同源中间件保护，未登录返回 `401`。

## 验收条件

- [ ] Given 用户选择受支持的本地图片，When 上传并保存资料，Then 头像预览和导航头像使用平台私有文件地址。
- [ ] Given 用户选择非图片、超限或内容签名不匹配的文件，When 上传，Then 显示可操作错误且不更新已生效头像。
- [ ] Given 用户移除头像并保存，When 刷新页面，Then 显示昵称首字且资料接口不再保留头像引用。
- [ ] Given 用户输入正确当前密码和符合要求的新密码，When 提交，Then 密码修改成功，当前会话可继续访问，其他旧会话失效。
- [ ] Given 当前密码错误、两次新密码不一致或新密码过短，When 提交，Then 不更新密码并显示错误提示。
- [ ] Given 用户尝试使用外部 URL 或他人素材作为头像，When 调用资料接口，Then 请求被拒绝且原头像保持不变。
- [ ] Given 页面在窄屏打开，When 使用头像和密码表单，Then 控件不溢出并可通过键盘操作文件选择、提交和错误提示。
- [ ] 旧用户资料中的历史外部头像仍可展示；旧客户端只修改昵称时不被新头像校验阻断。

## 边界情况

- 上传成功但用户未保存资料时可能留下未引用的素材，沿用现有素材生命周期和清理策略。
- 修改密码请求重复提交时，每次成功请求都会轮换 session；旧 Cookie 不可继续使用。
- 当前会话在密码修改前已经失效时，接口返回 `401`，不修改密码。

## 实现提示

- 复用 `POST /api/files`，不要把图片字节或第三方 URL 写入用户表。
- 资料接口保存头像前查询 `assets`，同时验证 owner、未删除和 `image/*` 内容类型。
- 密码修改使用现有 `hashPassword`、`verifyPassword` 和 session 表；会话删除与密码更新放在同一数据库事务中。

## 验证计划

- 自动化检查：认证单元测试、`pnpm check`、`pnpm check:full`。
- 人工检查：本地上传 JPG/PNG、移除头像、登录状态下修改密码，以及旧会话失效行为。
- 需要凭据或外部环境的检查：需在配置 PostgreSQL 的开发环境执行真实登录、头像上传和旧会话失效检查；OSS 已配置的环境可额外检查头像签名地址。

## 上线与回滚

不新增环境变量和数据库字段，不需要 migration。回滚代码后已有本地头像资产仍保留为普通私有素材，历史头像地址可继续按原逻辑展示。

## 实现结果

已实现个人资料页的本地图片头像上传、预览/移除和资料保存，新增密码修改接口与表单，并限制新头像只能引用当前用户的图片素材。`pnpm check` 与 `pnpm check:full` 已通过；真实帐号流程和 OSS 签名地址仍需在部署环境人工验收。
