# 多用户生产平台：帐号、额度、私有资产与后台任务

- 状态：accepted
- 负责人：待定
- 创建日期：2026-09-05
- 相关 issue / ADR：后续实施需新增生产架构 ADR，并复审 [ADR-001](../docs/decisions/001-oss-material-storage.md)

## 背景与问题

本规格把用户提出的五组需求扩展为生产化契约。主体代码已经实现；依赖真实 PostgreSQL/Redis/OSS、供应商帐号和 GPU 的项目仍按末尾验证计划执行上线验收。

当前事实已核对 [DESIGN.md](../DESIGN.md)、[API 文档](../docs/api.md) 和实际调用链：

- [创建任务](../server/api/generations/index.post.ts) 先提交供应商、再保存本地记录；保存失败时可能产生有费用却没有平台记录的任务。
- [任务服务](../server/services/generations.ts) 在查询请求内刷新和归档；没有帐号归属、额度预留和跨实例协调。
- [OSS 工具](../server/utils/oss.ts) 写入公开对象，[文件接口](../server/api/files/[id].get.ts) 无鉴权并设置一年公共缓存。仅增加用户目录无法使历史公开素材变成私密。
- [ComfyUI 队列操作](../server/api/comfyui/queue.post.ts)、[历史列表](../server/api/comfyui/history/index.get.ts) 和 [WebSocket 代理](../server/routes/api/comfyui/ws.ts) 直接对应共享实例；全局事件、文件和控制操作均需重新划分权限。
- [Dockerfile](../Dockerfile) 的运行镜像为 Node Alpine，只复制 Nuxt 构建结果，不包含 Python、Git、ComfyUI 与模型。[模式解析](../server/services/comfyui/config.ts) 尚未强制生产环境使用 remote。
- 当前供应商目录包括百炼、MiniMax、Kling、Seedance、RollDek、Runway。同名模型经不同渠道调用时，能力与采购价格不能互相替代。

## 目标

- 用户拥有可追溯的帐号、私有素材、作品、工作流和额度流水。
- 每次生成有明确的费用预估和结算依据；并发提交、重试、故障恢复不能重复扣费或无上限消费。
- 页面关闭后任务仍能推进；Web 与 worker 可分别扩容和重启。
- 管理员能管理用户、查看其全部生成、调整额度与价格、处理故障，并留下操作记录。
- ComfyUI 在独立 GPU Docker 服务运行，生产应用只通过受控 remote 连接访问。

## 非目标

- 首版建议不做在线支付、订阅、发票、推广返佣、团队共享空间、公开作品社区；用户额度先由管理员发放。
- 首版不做任意代码型自定义节点安装、任意模型下载及无限制工作流执行。
- 本次不代替部署方创建云数据库、Redis、OSS Bucket、供应商帐号或 GPU 主机。
- 本次价格调研用于确定计费结构，不能当作覆盖所有模型与参数组合的可上线价格库。

## 用户流程

1. 游客可以浏览公开介绍与模型能力。导航显示用户图标，点击打开注册/登录弹窗；触发上传、生成、作品库或工作流保存时要求登录。
2. 建议首版支持邀请注册、邮箱验证、邮箱密码登录、找回密码与退出。完成登录后恢复此前创作草稿，不自动提交付费任务。
3. 登录后图标切换为用户头像；未上传头像时展示默认头像或昵称首字。菜单包括个人资料、可用/预留额度、消费记录、存储用量和退出；管理员导航额外显示控制面板。
4. 用户上传素材到个人素材库，选择模型与参数后看到预估额度、计费项和最高授权扣费额。参数变动后重新报价，余额不足时提示缺口。
5. 提交成功后显示排队、执行、结果归档进度；用户离开页面后任务继续。失败、取消、状态待确认分别解释费用处理和可执行动作。
6. 任务完成后显示实际扣费、结果预览和下载；“重试归档”沿用原生成，“再次生成”创建新任务并重新报价。
7. 管理员进入控制面板，按用户、模型、时间、生成/归档/结算状态查找任务，查看明细、发放额度或处理异常。

## 行为契约

### 1. 帐号与授权

- 首版角色为 `user`、`admin`；角色来自服务端。首次管理员通过部署引导或受控命令创建，不接受注册请求指定角色。
- 帐号状态至少区分待验证、正常、停用。密码使用成熟鉴权方案的安全哈希；会话通过安全 Cookie 管理，支持过期、退出、密码重置后撤销和管理员停用后失效。
- 生产接口按来源策略处理 CORS、CSRF 和 WebSocket Origin；不能沿用当前对全部 API 开放的跨域策略。
- 用户、任务、素材、工作流与执行记录建立服务端所有权。所有列表、详情、修改、下载、签名、事件订阅都验证归属，不能只在导航或页面拦截。
- 未登录访问私有 API 返回 401；普通用户调用管理接口返回 403；访问不存在或他人私有资源统一返回 404，避免泄漏其存在性。
- 私有响应不得进入跨用户公共缓存；退出后清理客户端帐号相关缓存和实时连接。
- 停用用户立即禁止新任务并撤销会话；已经提交的任务继续归档和对账，不能简单删除或假定取消成功。

### 2. 额度与费用

**分开记录三种量：供应商用量、平台采购成本、用户消费额度。** 同一模型经百炼、Runway、RollDek 或直连提供时分别配置，不能按模型显示名称复用单价。

价格规则至少包含：渠道、精确模型 ID/版本、地域、生成模式、分辨率、音频选项、计费单位、阶梯或档位、最低消费、取整规则、币种、来源链接、核对时间、生效区间。平台售卖规则另存额度换算、加价或固定售价；不能让管理员输入任意可执行代码作为公式。

支持的计费结构包括输出秒数、输入/参考视频秒数、参考图数量、视频 token、固定规格每次费用，以及这些计费项的组合。媒体实际时长和分辨率由服务端验证，不能信任浏览器填写的计费参数。

计费流程建议如下：

1. 服务端生成短期有效报价，绑定用户、规范化请求摘要、价格版本和最高扣费额；更换素材或参数后旧报价不可复用。
2. 提交时在同一数据库事务内创建任务、预留额度、写入待派发事件。可用额度 = 余额 − 未结清预留；并发提交不得令可用额度为负。
3. worker 提交上游。明确未受理则释放预留；提交超时且无法确定是否受理，进入待核对状态，不立即重提或退款。
4. 获得可信实际用量后，按提交时价格快照结算并释放差额。缺少上游用量时，只能按已验证的固定规则计算并标注来源；无法确定则待核对，不能伪装为精确账单。
5. 智能时长等不确定费用必须有可验证的上限才能报价；无上限的组合首版不开放。实际费用意外超出用户授权额时，超出部分记平台差异并告警，不静默额外扣款。
6. 每笔预留、消费、释放、退款、赠送、人工调整均有不可覆写流水、关联任务和幂等键。管理员通过新增调整流水修改余额，记录理由，不能直接改历史账目。

| 结果                         | 建议的用户额度规则                                                     |
| ---------------------------- | ---------------------------------------------------------------------- |
| 校验失败、未提交、明确未受理 | 不扣费，释放预留                                                       |
| 生成成功                     | 按快照与实际用量结算                                                   |
| 供应商明确生成失败           | 首版建议不向用户收费；上游如仍扣费，另记平台成本与差异                 |
| 生成成功但归档暂时失败       | 保留成功状态，归档重试不重复收费；超过交付期限按预先公布的补偿规则处理 |
| 提交超时、状态未知           | 标记待核对；限定自动核对时限并升级人工处理，不能无限冻结额度           |
| 取消                         | 未发往上游可释放；已发送需确认上游结果，不能将点击取消视为已停止计费   |

价格修改走草稿、模拟报价、发布新版本；已受理任务保持旧快照。未受理的过期报价要求重新展示。规则缺失或范围不匹配时禁止付费提交；明确的管理员赠送模式也必须计入平台成本预算。

### 4. 滥用和成本保护

- 独立控制注册/登录频率、每用户提交频率、每用户在途任务数、provider/model 并发、单任务费用上限、用户日预算和平台日预算；预算统计包含在途预留。
- IP 限流作为辅助，不能替代帐号配额。建议首版用邀请码控制注册，赠送额度设置总预算和领取幂等性。
- 保留全局及渠道暂停新提交开关；触发预算或故障熔断后，已存在任务仍可查询、归档和结算。
- 上传和远程素材导入限制实际字节数、类型、时长与用户空间；检测内容类型，安全处理文件名和路径。
- 对服务端下载的 URL 校验公网目标、重定向和解析结果，阻止访问内网/云元数据地址；设置超时、实际下载量和并发上限。
- 区分网络故障、参数错误、内容审核拒绝等，不对永久拒绝自动反复提交；展示可操作错误并记录脱敏原因。

### 5. 私有素材与存储空间

- 默认每用户一个逻辑空间：PostgreSQL 记录 owner 和元数据，OSS 私有 Bucket 保存输入、结果、缩略图和预览。首版无需每用户创建一个 Bucket。
- 对象路径可用用户与资产 UUID 分层，但权限依据服务端资产记录；对象不可因知道路径而公开访问。
- 引入平台 `assetId` 引用并验证所有权。数据库持久化 object key 等稳定标识，不把会过期的签名 URL 当资产身份或长期视频地址。
- 浏览器经鉴权获得短期播放/下载地址；明确链接在有效期内可被持有者使用。需要即时撤销访问的场景走鉴权代理；不能声称退出会立刻撤销所有已签发 OSS 链接。
- 供应商读取私有素材采用专用受限授权：提交时签发，覆盖预期排队及读取窗口。超长任务需供应商资产上传机制，或可在服务端校验任务有效性的授权下载代理。不能假定签发新 URL 就能替换供应商已经收到的旧 URL。
- 无法确认素材授权时限足够的 provider/model 组合，不向用户开放私有素材生成。
- 素材可提供外链导入，但先作为受控导入任务复制并校验到个人空间，避免绕过归属、配额和媒体验证。
- 空间显示已用量、上传预留量、结果归档预留量与上限；提交前为输出留出合理空间，归档异常溢出设受控缓冲与告警，防止付费成功却无法交付。
- 定义回收站期限、临时素材期限、孤儿对象清理和引用保护。任务在途时所需输入不能提前物理删除；任务记录、账目和媒体字节采用不同保留策略。
- 管理员按权限查看所有用户生成及相关素材，预览和下载留审计记录；向用户说明管理员可访问的范围。产品不宣称管理员不可读或端到端加密。

### 6. 生产存储与任务架构

建议保留一个业务代码库，部署为 Web/API、worker、PostgreSQL、Redis/队列和独立 ComfyUI GPU 服务。OSS 承载媒体，队列消息主要存平台任务 ID。

| 组件             | 职责与数据边界                                                                                  |
| ---------------- | ----------------------------------------------------------------------------------------------- |
| PostgreSQL       | 帐号、会话、任务、素材元数据、工作流及版本、执行记录、钱包预留/流水、价格版本、审计、待派发事件 |
| OSS              | 私有素材、输出、预览；不作为帐号或任务状态事实源                                                |
| Redis/队列       | 调度、延迟轮询、限流与短期租约；不作为余额唯一事实源                                            |
| worker           | 提交、轮询/处理回调、用量归一化、结果归档、结算、重试和清理                                     |
| Web/API          | 鉴权、校验、报价、事务受理、查询和向用户推送状态                                                |
| ComfyUI GPU 服务 | 执行受控工作流；平台负责所有权、配额、调度和输出归档                                            |

- 任务与待派发事件在同一数据库事务提交，再异步入队（transactional outbox），避免数据库写成功但任务未入队。队列丢失后可从数据库重新派发。
- 任务先落库再调用供应商；记录每次 submission attempt、幂等键和上游任务 ID。供应商支持幂等时复用同一键；不支持时对受理不明的请求进行核对，不自动盲目重提。
- 按任务阶段拆分提交、轮询、归档、结算；遵守供应商限流，指数退避与抖动，有重试上限、死信和人工恢复入口。供应商支持可信回调时可优先使用，但仍保留补偿检查。
- 队列按可能重复投递设计；数据库唯一约束、状态条件更新和事务保证任务效果幂等。分布式锁只减少竞争，不能作为防重复扣费的唯一机制。
- 租约过期后旧 worker 不得覆写新结果；使用版本校验或 fencing token。归档采用确定对象标识、完整性校验及成功对象复用，避免多个输出副本。
- `GET` 列表和详情只读平台状态并分页；显式“刷新”变为入队请求。用户刷新页面不触发一轮付费提交或全表轮询。
- 生成状态、归档状态、结算状态分别保存，避免“生成失败”“归档失败”“账单待核对”混为一谈。提交/调度阶段可作为内部状态，具体映射由后续共享契约规格确定。
- 生成终态不再常规轮询。旧实现的“成功后显式回源换下载地址”与仓库终态限制存在边界差异，实施规格需明确：默认复用已保存输出信息；确需换链时定义受限归档恢复操作，不能重新提交或降级成功状态。
- 区分数据库 migration version、记录 payload `schemaVersion` 和工作流图自身 version；提供迁移日志、兼容读取与未知版本错误。
- 工作流定义、不可变版本和执行记录分开。执行绑定具体版本、owner、资源预算、输出资产、成本；可与供应商任务共享管理视图，无需把 ComfyUI 原始图塞入 `GenerationRequest`。

### 7. ComfyUI 生产部署与多用户执行

- 生产启用 ComfyUI 时必须显式为 `remote` 且配置受控地址；`auto`、`local` 或缺失必需地址作为配置错误。允许显式关闭模块，不影响云供应商生成。
- 开发环境保留 local/auto。生产页面隐藏安装/本地启停，服务端也拒绝这些端点，不能只隐藏按钮。
- 独立 Docker GPU 服务固定 ComfyUI、Python、PyTorch、CUDA 和已审核节点版本；模型卷只读，输入/输出/临时目录可清理，具备健康探测、资源上限和版本回滚。具体组合需对目标 GPU 实测；不假定存在满足需求的官方 Docker 镜像。
- ComfyUI 官方文档说明服务通过 Python 启动并提供远程监听，GPU 依赖按设备安装；这支持拆分运行时，不能证明具备平台级租户隔离。[官方服务通信说明](https://github.com/comfy-org/docs/blob/main/development/comfyui-server/comms_overview.mdx)、[官方故障排查与依赖说明](https://github.com/comfy-org/docs/blob/main/troubleshooting/overview.mdx)。
- GPU 服务只在可信网络内向平台开放，跨主机连接使用经过认证的受保护通道；浏览器 HTTP/WS 均经平台鉴权代理。
- `promptId`、client/session、输入文件和输出文件映射到平台执行记录；历史、队列、进度与预览按 owner 过滤。客户端提供的 `clientId` 不是授权凭据。
- 清空共享队列、卸载模型、释放全局显存等是管理员运维操作。普通用户只能取消自己的待执行任务；运行中取消仅在能原子保证目标仍为该用户任务时执行，否则不开放全局 interrupt，避免检查后任务切换误杀他人。
- `object_info` 等节点元数据也可能包含共享输入文件候选项，应替换为当前用户可用资产；只过滤历史列表并不完整。
- **首版建议任意工作流执行仅向管理员开放；普通用户先使用审核后的模板。** 后续开放自定义图需服务端节点白名单、参数/文件引用验证、运行时限、输出上限和资源预算；禁止通过节点读取他人文件、任意路径或执行任意脚本。
- 单个共享容器不提供每用户执行环境隔离。若需要任意工作流，另行设计按作业/租户隔离实例、目录和网络权限，重新评估容量与成本。
- GPU 自托管不按生成视频秒数推定成本。首版建议模板固定额度并设最大 GPU 时间；另记录实际执行时间、设备和平台成本。API 节点如调用外部付费服务需纳入独立预算，否则禁用，不能绕过钱包。
- 管理员查看“用户全部生成”同时包含 provider 生成和 ComfyUI 执行输出；用户侧是否合并作品库由后续 UI 规格决定。

### 8. 管理控制面板与运行保障

控制面板首版建议包含以下六部分：

| 页面       | 能力                                                                  |
| ---------- | --------------------------------------------------------------------- |
| 概览       | 在途任务、失败率、归档积压、日预算与剩余额度                          |
| 用户       | 搜索、停用、角色管理、存储/并发配额、查看用户任务                     |
| 任务与资产 | 所有渠道及 ComfyUI 执行，生成/归档/结算分状态筛选，重试归档和异常核对 |
| 额度与价格 | 赠送、调整、退款流水；规则模拟报价、生效版本、采购成本和售卖规则      |
| 渠道与算力 | 启停新提交、模型对用户的可用性、并发、预算、GPU 服务健康              |
| 审计       | 操作人、对象、时间、理由、修改前后值；素材访问与下载记录              |

- 技术能力继续由 `catalog.ts` 和适配器定义；控制面板只能限制可用范围和配置价格，不允许宣称适配器不支持的模型能力。
- 管理员同样不能绕过平台成本预算；角色变更不能由普通用户完成，且应防止误删最后一个管理员。
- 首版后台不回显供应商密钥；密钥管理继续走私有配置。将来支持后台更换密钥时单独设计加密保存、轮换和访问控制。
- 增加队列等待时间、worker 心跳、上游 429、提交待确认数量、归档失败率、长时间预留、异常成本、空间余量告警；日志用 task/attempt ID 串联并去除签名链接和凭据。
- 备份 PostgreSQL，并验证恢复；媒体按约定配置删除保护/版本策略。明确恢复时间与允许数据丢失窗口，不能只有“备份成功”而无恢复演练。

## 验收条件

- [ ] 登录弹窗可通过键盘完成操作，具有加载、错误、验证和成功状态；窄屏可用，关闭后恢复焦点。
- [ ] 用户 A 无法通过 ID、签名接口、WebSocket、节点文件候选项或 ComfyUI 预览读取用户 B 的私有内容；管理员可查看两类生成且留审计。
- [ ] 并发提交超过可用额度时只有预算内任务受理；相同幂等键只产生一个任务和一组账目，相同键配不同参数返回冲突。
- [ ] 覆盖输入视频收费、固定档位、token、最低消费、多参考素材、取整和自动时长；缺失规则不能提交。
- [ ] 管理员改价不影响已受理任务；更改报价参数或伪造媒体时长不能降低服务端扣费。
- [ ] 供应商受理后平台超时，任务进入核对而非无条件重提；不会因刷新、重复回调或 worker 重启产生重复收费。
- [ ] 数据库受理后队列不可用，恢复后能继续执行；重复投递及租约失效不会重复结算或让旧 worker 覆写状态。
- [ ] 浏览器关闭后任务继续完成并归档；分页查询不会调用供应商；归档失败保留生成成功且可重试。
- [ ] 私有对象无法匿名读取，授权播放支持所需 Range/HEAD，链接过期可重新鉴权；长时间排队不导致供应商素材授权无声失效。
- [ ] 上传与任务并发能正确预留空间；取消上传释放预留，清理不删除在途任务仍引用的素材。
- [ ] 生产拒绝 local/auto，ComfyUI 停用或不可达不影响其它渠道；普通用户不能操作共享队列和全局 interrupt。
- [ ] 历史任务、素材和工作流迁移后 ID 与引用保持一致，旧公开访问入口被关闭；未确定归属的数据不会向新注册用户开放。
- [ ] 备份恢复演练、脱敏故障恢复测试和适用生产检查通过后，方可将相应实施规格标记 completed。

## 边界情况

- 取消请求与上游成功同时到达；冻结额度期间管理员调整余额或停用用户。
- 同一请求在多个标签页提交；worker 在上游受理、OSS 上传完成或扣费提交后崩溃。
- 回调重复、乱序或伪造；上游任务成功但没有输出，或临时链接过期后供应商不再保留任务。
- 优惠到期、模型别名变更、地区或币种切换、上游用量缺失、最终成本超预估。
- 历史对象仍有 public-read ACL 或 CDN 缓存；只改 Bucket 策略未覆盖对象权限；已被第三方下载的内容无法收回。
- 工作流改名/覆盖后旧执行需可追溯；用户删除素材但进行中任务或历史复现仍引用它。
- GPU OOM、实例重启、未归档输出清理、用户试图通过节点参数引用他人文件。

## 实现提示

建议按下列顺序拆分交付，每阶段补充自身 API、迁移和验收规格；涉及长期边界的取舍另写 ADR。

| 阶段                | 范围                                                                                                 | 完成后可做什么                         |
| ------------------- | ---------------------------------------------------------------------------------------------------- | -------------------------------------- |
| A：生产底座与所有权 | PostgreSQL、迁移方案、帐号/session、owner 校验、私有 OSS 与历史资源迁移；同步限制生产 ComfyUI remote | 在受控环境验证帐号和资产隔离           |
| B：可计费任务闭环   | worker、队列/outbox、先落库提交、钱包预留/流水、报价、幂等和对账、最小管理面板                       | 邀请少量用户，用管理员额度进行完整试用 |
| C：运行与 GPU       | 完善后台、预算熔断、清理/告警/恢复演练、独立 GPU 镜像、ComfyUI owner 与模板限额                      | 在明确容量范围内扩展多用户使用         |
| D：商业与体验扩展   | 在线充值/订阅、团队空间、可撤销分享、批量任务、工作流版本比较和更细执行隔离                          | 依据真实使用量决定增量投入             |

在 B 完成前不开放无预算保护的公众生成；ComfyUI 向普通用户开放还需通过 C 的隔离与资源验收。

建议默认值是：邀请注册、邮箱帐号、管理员发额度、个人私有空间、模板式 ComfyUI 普通用户入口。注册开放程度、额度售卖比例、补偿期限、存储保留期与生产容量仍是产品决策，不能把建议数字当已批准配置。

## 验证计划

- 本次只新增草案：执行 `pnpm check` 和 `git diff --check`。
- 后续实现涉及 API、契约、存储和部署，执行 `pnpm check:full`，新增针对越权、并发额度、幂等、提交不明和归档补偿的确定性测试。
- 人工检查：注册登录、草稿恢复、额度不足、取消待确认、结果归档失败、后台管理、移动端与无障碍状态。
- 外部环境检查：测试 PostgreSQL/Redis 故障恢复、私有 OSS 授权与缓存、供应商对签名素材的读取、真实 GPU 执行与重启恢复。付费验证需在明确授权的测试预算内进行。
- 官方价表逐模型复核与账单对账未完成前，不能宣称生产计费已验收。

## 上线与回滚

- 迁移前备份 `.data` 与对象清单，暂停新提交并处理在途任务。先 dry-run 统计，再按稳定 ID 幂等导入，校验数量、引用关系、文件完整性和任务状态。
- 历史无 owner 数据建议进入隔离的 legacy 管理空间，经过核对再分配给指定帐号；不自动归属于首个注册用户，不补扣未知历史费用。
- 历史公开对象迁移到新的私有路径，清理公开 ACL、旧 URL 入口及 CDN 缓存，并说明此前泄露或下载的副本无法撤销。该步骤需要独立资产清单与执行记录。
- 新版与旧版不能无协调地同时提交同一批任务或写两套账。切换采用明确读写边界；金额流水以数据库为准。
- 回滚优先停用新提交和切回兼容 schema 的应用版本，保留只读查询与恢复 worker。不得恢复无鉴权的公网旧版或通过旧数据库快照抹掉切换后的消费流水。
- 接受实施时同步 `shared/types/`、运行时 schema、`DESIGN.md`、`docs/api.md`、开发文档及环境配置；历史已完成规格保留原貌。

## 实现结果

已实现帐号与 session、邀请注册、头像入口、角色和 owner 校验；PostgreSQL schema/migration、历史 `.data` 导入脚本、private OSS 资产；报价、额度预留/结算流水、幂等生成受理、平台预算；BullMQ worker、transactional outbox、后台轮询/归档；管理员用户、额度、价格、全量任务、异常核对和审计界面；独立 ComfyUI GPU 镜像与生产 Compose，并强制生产 remote 模式。共享 ComfyUI 任意工作流首版只向管理员开放。

默认 migration 中的价格是带官方来源链接的内部占位规则，供系统安全拒绝或受控试用，不能视为完成所有 provider/model 的商业价格核验。Kling、RollDek 与 Seedance 的帐号适用价格、真实 OSS 签名读取、故障恢复、备份恢复和目标 GPU 作业仍需在部署环境验收，因此本规格保持 `accepted`，不标记 `completed`。
