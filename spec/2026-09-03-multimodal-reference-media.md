# 多模态参考多素材上传

- 状态：accepted
- 负责人：
- 创建日期：2026-09-03
- 相关 issue / ADR：

## 背景与问题

供应商官方 API 已支持同一请求提交多张参考图、多个参考视频或多个参考音频，但创作台每种素材只有一个输入槽位，后续上传会覆盖前一份素材。部分跨类型组合上限也没有进入统一能力校验。

## 目标

- 创作台支持按模型能力多选文件、连续添加公网 URL、逐条查看和删除素材。
- 能力目录声明单类数量和必要的跨类型组合限制，前后端使用同一套校验逻辑。
- 支持 Seedance 2.5 官方的 30 图 / 10 视频 / 10 音频请求规模，同时保留各模型自己的限制。

## 非目标

- 不实现视频编辑、延长或逐素材 `reference_voice` 的新任务语义。
- 不改变已持久化 `GenerationRecord.media` 的数组结构。
- 不在本次变更中增加供应商凭据或真实上游调用。

## 用户流程

1. 用户选择支持多模态参考的模型。
2. 在对应素材卡片中一次多选文件，或逐个粘贴公网 URL；每份素材显示名称/URL，可单独删除。
3. 达到模型单类上限后，继续添加入口禁用并显示上限；违反跨类型组合限制时保留原选择并提示原因。
4. 提交时前后端再次校验，绕过前端的无效组合返回 422。

## 行为契约

- `GenerationRequest.media` 允许同一 `type` 重复出现，最多 50 份。
- `ProviderMediaLimit.max` 表达单类上限；`MediaCombinationLimit` 表达跨类型或条件组合上限。
- Wan 3.0：参考图最多 10 张、视频最多 5 个、音频最多 5 个；视频和音频总时长分别不超过 15 秒。
- Wan 2.7 R2V：参考图与参考视频合计最多 5 个。
- Kling V3 Omni：仅参考图时最多 7 张；带参考视频时视频最多 1 个且参考图最多 4 张。
- Seedance 2.0 / Fast / Mini：9 图 / 3 视频 / 3 音频；Seedance 2.5：30 图 / 10 视频 / 10 音频。
- UI 上传本地文件仍经 `/api/files`，每个文件独立上传并保留独立 URL；公网 URL 可逐条添加。

## 验收条件

- [x] 多素材卡片支持 `input[multiple]`，展示数量、列表、名称/URL 和逐条删除。
- [x] 首帧/尾帧等单素材能力仍限制为 1 份。
- [x] 前端按当前模型能力阻止单类超限和跨类型组合超限。
- [x] 服务端按同一共享校验拒绝单类超限和跨类型组合超限。
- [x] API schema 的总素材上限覆盖 30 图 + 10 视频 + 10 音频的最大模型组合。
- [x] API 文档说明重复 `media.type` 的提交方式。

## 边界情况

- 批量上传中某一份失败时，已成功上传的文件不应伪装成已加入素材列表，并显示可操作的失败提示。
- 切换模型后若已有素材超过新模型上限，保留已有素材以便用户删除，并在提交前提示具体限制。
- Kling Omni 参考视频与参考图的条件上限、Wan 2.7 R2V 图视频合计上限必须在服务端执行，不能只依赖供应商报错。
- 旧任务记录中的单素材或重复素材数组均可正常读取和展示。

## 实现提示

- 素材数量限制继续由能力目录驱动，页面不复制供应商名称或模型 ID 判断。
- 共享校验返回结构化错误，服务端负责转换为 422 文案，前端负责转换为可读提示。

## 验证计划

- 自动化检查：`pnpm check`、`pnpm check:full`。
- 人工检查：Wan 3.0、MiniMax H3、Seedance 2.0、Seedance 2.5、Wan 2.7 R2V、Kling Omni 的多文件选择、URL 添加、删除、超限和混合组合；移动端检查素材列表滚动与按钮可用性。
- 需要凭据或外部环境的检查：不提交真实上游任务；如需联调，使用脱敏公开 URL 和专用测试账号。

## 上线与回滚

无存储迁移和新增环境变量。回滚前端组件会恢复单槽位展示；重复 `media` 数组仍可被旧服务读取，但旧服务可能按最后一份或上游行为处理，因此回滚后应避免提交多素材任务。

## 实现结果

- `MediaSlot` 改为多选文件、逐条展示/删除和连续 URL 添加。
- 能力目录补齐 Wan 3.0、Wan 2.7、Kling Omni 的数量与组合限制；统一校验复用到前端和服务端。
- API 总素材上限调整为 50，覆盖 Seedance 2.5 的官方最大组合。
- 尚未执行真实供应商生成调用。
