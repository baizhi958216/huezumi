# 多模态创作平台：文章、图片、视频与短剧项目

- 状态：draft
- 负责人：待定
- 创建日期：2026-09-16
- 相关 issue / ADR：实施前需新增“创作项目与派生资产”ADR；沿用现有多用户、私有资产、计费与后台任务架构

## 背景与问题

forkvdo 当前是以 AI 视频生成为核心的平台：普通用户可在创作台提交视频任务，平台通过统一视频请求、供应商能力目录、报价、额度预留、后台 worker 和私有 OSS 完成生成与交付。图片创作主要存在于管理员 ComfyUI 工作流，文章创作、普通用户图片生成、跨模态作品版本和短剧编排尚未形成平台能力。

目标产品需要同时支持三类使用方式：

1. 用户只写一篇文章、只生成一张图片或只生成一段视频。
2. 用户在一个项目中从文章继续生成分镜、画面和视频。
3. 用户引用已经生成的文章和图片，局部修改提示或参数后生成短剧镜头，并能够继续编辑、重新生成和导出。

仅把“文章”和“图片”增加到现有视频表单不能满足这些需求。现有 `GenerationRequest` 的模式、分辨率、时长、音频和结果字段均具有明确视频语义；文章内容还需要编辑与版本，图片和视频需要多候选结果，短剧需要场景顺序、来源追踪和镜头级失败恢复。平台需要一层独立于供应商任务的创作领域模型。

本规格定义目标产品、用户流程、页面、数据关系、任务行为、计费边界和分阶段交付范围。它是待评审需求，不表示下述能力已经实现。

## 产品定位

forkvdo 是面向个人创作者的多模态 AI 创作平台。用户既可以快速使用单项工具，也可以围绕一个项目完成从想法到文章、分镜、画面、视频和成片的连续创作。

产品体验遵循以下原则：

- **独立可用**：文章、图片和视频不要求用户先完成前一阶段。
- **自然衔接**：任何已保存作品都可以成为后续创作的输入。
- **版本明确**：派生内容绑定输入的具体版本，源内容后续修改不会偷偷改变历史结果。
- **镜头级控制**：短剧按分镜和镜头生成，单个镜头失败或不满意时可以独立处理。
- **用户确认优先**：系统可以提出分镜、提示词和素材建议，但不会自动连续产生多笔付费任务。
- **供应商解耦**：页面使用平台能力，不暴露供应商原始协议；模型差异由能力目录驱动。
- **操作界面克制**：创作页只展示完成当前任务所需的信息，不使用首页式营销文案。

## 目标

- 普通用户能够创建、编辑、保存和版本化 AI 文章。
- 普通用户能够通过文字或参考图生成图片、选择候选结果并继续编辑。
- 普通用户继续使用现有供应商生成视频，并可引用项目中的文章片段、分镜和图片。
- 用户能够把文章转换成可编辑分镜，逐镜头生成画面和视频，最后编排并导出短剧。
- 独立创作与项目创作使用同一套作品资产、所有权、计费、任务和作品库体系。
- 每个生成结果能够回答“由哪个项目、内容版本、分镜、参考素材、模型和参数生成”。
- 页面刷新、关闭或 worker 重启不会丢失已受理任务、编辑内容或额度状态。
- 现有视频任务和已持久化 `GenerationRecord` 保持可读取、可播放和可结算。

## 非目标

- 首版不提供多人实时协同、团队空间、审阅评论或公开内容社区。
- 首版不提供完整专业剪辑器；不承诺替代 Premiere、DaVinci Resolve 等工具。
- 首版不自动发布到抖音、快手、Bilibili、YouTube 或其他第三方平台。
- 首版不开放普通用户任意 ComfyUI 工作流、任意节点、任意模型下载或执行环境访问。
- 首版不提供在线文档导入、事实核查、网页检索、引用管理或学术论文写作工具。
- 首版不保证跨供应商、跨模型的人物身份绝对一致；只能通过参考资产、固定种子和模型能力提高一致性。
- 首版不提供多人配音市场、数字人训练、声音克隆或版权授权交易。
- 本规格不确定具体供应商名单和最终价格；实际开放能力以能力目录和已发布价格规则为准。

## 用户与核心场景

### 1. 快速独立创作

用户从创作台选择“文章”“图片”或“视频”，填写必要输入并生成。首次保存时平台自动创建一个项目，或由用户选择已有项目。作品出现在作品库中，后续可继续进入其他阶段。

### 2. 从故事到短剧

用户输入故事想法，生成并编辑文章，确认一个文章版本后生成分镜。用户逐个调整分镜，选择需要的画面，生成图片候选并选定参考图，再为每个分镜生成视频。全部镜头准备完成后，用户排列顺序、调整字幕和基础音频，提交合成并下载成片。

### 3. 从图片到视频

用户上传或选择一张已有图片，进入视频创作，补充动作、镜头和时长要求。生成成功后结果保留对参考图版本和视频参数的引用。

### 4. 从旧作品继续创作

用户在作品库打开一篇文章、一张图片或一段视频，通过“继续创作”选择目标模块。系统带入可用上下文，但在提交前允许用户查看、删除或修改引用。

## 信息架构与导航

### 全局导航

登录用户的普通导航固定为：

| 导航项   | 路径候选     | 用途                                   |
| -------- | ------------ | -------------------------------------- |
| 创作台   | `/studio`    | 新建与继续文章、图片、视频创作         |
| 作品库   | `/projects`  | 浏览项目及其中的文章、图片、视频和成片 |
| 我的空间 | `/dashboard` | 额度、存储、最近项目、素材和模型概览   |

管理员在上述导航后继续显示“控制面板”；“工作流”并入创作台内部，与文案剧本、视频生成同级切换，不再占用全局导航。Logo、菜单名称、图标、顺序和激活状态必须由现有 `AppHeader` 和 `app-navigation.ts` 统一提供；任何业务页面不得复制另一套全局导航。

### 创作台层级

创作台默认打开“文案剧本”，分为两层：

1. **项目上下文栏**：项目名称、保存状态和文章/画面/视频三个阶段。
2. **当前任务区**：左侧为当前阶段必要输入，右侧为编辑器或生成结果。

阶段导航不表示强制流程。用户可以从任意阶段开始，也可以在项目中来回切换。分镜属于文章到画面的结构化过渡，在文章页中创建和编辑，不增加第四个全局模块。

## 页面需求

### 1. 首页

首页负责说明平台价值和引导开始创作，不承担项目编辑功能。

- 主标题表达“从想法到完整作品”。
- 主操作为“开始创作”，次操作为“查看作品”。
- 用简短入口展示文章创作、图片生成和视频生成。
- 可以展示一组文章、图片和视频自然衔接的视觉示例。
- 不在首屏堆叠模型数量、复杂流程说明、计费规则或大量描述卡片。
- 游客点击需要保存或付费的操作时打开登录流程，登录后恢复入口意图但不自动提交。

### 2. 创作台入口与项目选择

- 新用户看到三个同级入口：文章、图片、视频。
- 最近项目用户优先看到“继续创作”和三个入口。
- 用户可新建项目、打开最近项目或选择不命名直接开始；第一次保存时要求命名或接受自动名称。
- 项目自动名称来自首个有效标题或提示词摘要，用户可以随时重命名。
- 切换项目时如有未保存文本，应自动保存成功后切换；保存失败则停留并给出重试。

### 3. 文章创作

#### 输入

- 创作类型：故事、短剧故事、文章、营销文案；首版至少开放故事和短剧故事。
- 核心创意或用户已有正文。
- 风格/基调、目标长度和可选受众。
- 可选引用项目中的人物设定、场景设定、图片或旧文章版本。
- 模型选择由文本能力目录提供；未选择时使用平台默认可用模型。

#### 编辑

- 正文使用专注的文档编辑器，支持撤销、重做、自动保存和字数统计。
- 用户可以选中一段进行改写、缩短、扩展或按自由指令修改。
- 全文生成和局部改写均先产生新版本，不能直接覆盖唯一副本。
- 用户可以查看版本时间、来源和生成模型，恢复旧版本时创建新的当前版本。
- 保存状态至少区分：正在保存、已保存、保存失败和离线未同步。

#### 输出

- 当前文章版本可继续生成分镜、生成配图或作为视频灵感来源。
- “生成分镜”必须显示将使用的文章版本和预计消耗；用户确认后才提交。
- 用户仍可在没有文章的情况下手工创建分镜。

### 4. 分镜编辑

每个分镜至少包含：

- 顺序号和可编辑标题。
- 对应的文章片段或来源说明。
- 画面描述。
- 人物、场景和道具引用。
- 动作、镜头类型、运镜和氛围。
- 对白、旁白和字幕文本。
- 目标时长和画幅。
- 当前选定的关键画面与视频镜头。

用户可以新增、复制、删除、合并、拆分和拖动排序分镜。AI 重新拆分时生成新的分镜版本；默认不覆盖用户已经修改或已经产生付费作品的分镜集合。

当文章产生新版本时，系统将现有分镜标记为“来源版本较旧”，允许用户继续使用、比较后更新或重新生成，不能自动覆盖。

### 5. 图片生成与编辑

#### 独立图片模式

- 输入提示词、反向提示词（模型支持时）、画幅、尺寸、候选数量和模型。
- 可选上传或引用一至多张参考图，具体数量、格式和大小由能力目录驱动。
- 支持文生图、参考图生图和图片编辑；局部重绘在具备遮罩编辑体验后开放。

#### 项目画面模式

- 用户先选择一个分镜，平台带入该分镜的画面描述、人物和场景引用。
- 用户提交前可以修改生成提示词，不反向修改文章或分镜正文。
- 一次任务可以返回多个候选图；用户可选择其中一个或多个保存到项目。
- 每个分镜只能有一个“当前关键画面”，但可保留多个历史候选和替代版本。
- “设为关键画面”不删除其他结果，也不触发新收费。

#### 编辑与再次生成

- 用户可以基于已保存图片创建编辑任务，记录原图、编辑指令和遮罩版本。
- “再次生成”创建新任务和新报价，不能覆盖旧结果或复用旧扣费。
- 用户可将任一图片带入视频模块，平台根据目标视频模型能力提示可否使用。

### 6. 视频生成

#### 独立视频模式

- 沿用现有文字、首尾帧和多模态参考模式。
- 供应商、模型、素材、画幅、分辨率、时长、音频等控件继续由 `/api/providers` 能力驱动。
- 在提交前展示准确报价、额度余额和参数限制。

#### 项目镜头模式

- 用户选择一个分镜，平台展示其文字要求和当前关键画面。
- 用户明确选择要引用的文章版本、分镜版本、图片和其他素材；系统可默认建议但必须可删除。
- 视频提示词是该次任务的快照。后续修改分镜不会改变已经提交的请求。
- 每个分镜可保留多个视频候选，并指定一个当前镜头。
- 单个镜头失败不改变其他镜头状态；用户可重试该镜头或更换模型重新报价。

#### 镜头时间线

- 时间线按分镜顺序显示当前镜头、时长和状态。
- 支持拖动排序、替换当前镜头、预览单镜头和连续播放。
- 首版只提供镜头顺序、裁切起止点、基础转场、字幕开关和音轨音量。
- 对源视频进行裁切或排序属于编排数据，不应修改或复制原始归档视频。

### 7. 合成与导出

- 用户选择画幅、输出分辨率、帧率、基础转场、字幕样式和音频策略后获得导出报价。
- 导出使用独立异步任务，记录所引用的镜头版本和编排快照。
- 导出中用户仍可编辑项目，但已运行任务继续使用提交时快照。
- 成功后生成新的成片资产，保留镜头源文件。
- 导出失败不删除镜头、不重复扣除已结算的镜头生成费用；导出任务自身按平台规则释放或结算预留。
- 首版提供 MP4 下载；分享链接、平台发布和多格式专业导出后续另行设计。

### 8. 作品库

- 默认按项目展示，不再把视频任务和 ComfyUI 输出拼成两种互不相关的卡片。
- 项目卡显示封面、名称、当前阶段、完成进度、更新时间和状态。
- 支持全部、创作中、已完成筛选和名称搜索。
- 打开项目进入其最后活动阶段；通过卡片菜单可重命名、复制、归档或删除。
- 项目详情可按“全部、文章、图片、视频、成片”浏览作品资产。
- 旧视频任务通过兼容视图显示为“历史视频”；用户继续创作时才创建或绑定项目。
- 管理员 ComfyUI 历史输出保留原有来源标识，迁移完成前不能伪装为普通项目资产。

### 9. 我的空间

- 展示可用额度、预留额度、存储空间和本月生成次数。
- 展示最近项目及其当前阶段，不重复完整作品库。
- 展示个人模型与上传素材入口；未开放的模型操作保持明确空状态。
- 展示最近额度流水，完整流水进入现有账单页面或详情。
- 不采用管理后台式密集图表，不出现普通用户无法操作的平台级数据。

## 视觉与交互规范

- 继续使用当前项目设计令牌：浅色 `#f7f8fa` 背景、白色提升面、细灰边框、近黑正文和少量 `#ff4d35` 强调色。
- 全局导航必须复用 `AppHeader`；普通用户菜单固定为创作台、作品库、我的空间。
- 图标统一使用项目现有 Lucide 图标，常规尺寸 16–18 px，避免粗线、填充图标、emoji 和超大装饰图标。
- 创作页面标题和控件使用功能性短文案；产品介绍、愿景和能力说明只出现在首页、帮助或空状态。
- 每屏只保留一个主操作。次要操作使用中性按钮或菜单，不与生成按钮争夺视觉焦点。
- 大屏创作区优先采用“输入 28%–32% / 结果 68%–72%”；文章编辑器可适当扩大正文区域。
- 空白是布局的一部分；不能为了展示能力把所有可选参数默认展开。高级参数按模型能力折叠。
- 生成结果优先展示作品本身；状态、参数和来源进入次级信息或详情抽屉。
- 加载使用骨架或局部进度，不阻塞整个项目。错误显示在对应任务或控件附近，并提供可执行动作。
- 键盘焦点、对比度、表单标签和弹窗焦点恢复符合现有无障碍约定。
- 桌面为首要创作体验；窄屏允许纵向堆叠和浏览、轻量编辑与任务提交，复杂时间线可提示使用桌面，但不能导致内容丢失。

## 领域模型与数据关系

下列名称为候选领域概念，最终表名和共享类型在实施规格中确定。

### CreativeProject

一个用户创作空间，包含文章、分镜、媒体资产和导出结果。

- `id`、`ownerId`、`schemaVersion`
- `name`、`description?`、`status`: `draft | active | completed | archived`
- `coverAssetId?`
- `lastActiveStage`: `article | image | video`
- `createdAt`、`updatedAt`、`deletedAt?`

### Document 与 DocumentVersion

`Document` 是稳定身份，`DocumentVersion` 是不可变内容快照。

- 文档类型、标题、当前版本 ID 和项目归属保存在 `Document`。
- 版本保存结构化正文、纯文本摘要、父版本、来源任务、创建者和创建时间。
- 自动保存可以更新尚未发布的 working revision；生成、派生和恢复操作必须固化版本。
- 文章派生的分镜绑定具体 `DocumentVersion`，不只绑定可变文档 ID。

### Storyboard 与 Scene

- `Storyboard` 保存项目、来源文章版本、版本号和当前状态。
- `Scene` 保存顺序、描述、对白、时长、画幅、镜头信息和结构化角色/场景引用。
- 场景被生成任务引用后，修改产生新 revision 或快照；历史任务继续指向旧快照。

### CreativeAsset

统一描述用户可见作品和素材元数据，不取代底层 `assets` 文件记录。

- 类型：`source_image | generated_image | source_video | generated_video | audio | final_video | thumbnail`。
- 保存 owner、project、底层文件/归档引用、MIME、尺寸、时长、状态和删除时间。
- 生成资产关联来源任务；上传资产关联原始 `assets` 记录。
- 一个资产可以被多个项目引用，但引用前始终验证 owner。

### AssetRelation

显式记录派生关系，建议包含：

- `input_to_job`：素材作为生成任务输入。
- `generated_from`：输出由任务或资产派生。
- `illustrates_scene`：图片属于某个分镜版本。
- `video_for_scene`：视频属于某个分镜版本。
- `selected_variant`：用户将候选设为当前作品。
- `included_in_export`：镜头被某个导出快照引用。

关系记录引用具体版本和资产 ID，不保存临时签名 URL。

### CreationJob

平台级任务外壳建议区分：

- `text_generation`
- `storyboard_generation`
- `image_generation`
- `image_edit`
- `video_generation`
- `composition_export`

每类任务使用独立、严格的 payload schema。外壳统一 owner、project、状态、幂等键、输入快照、报价、结算、供应商任务引用、错误和时间字段。

现有 `GenerationRequest` 和 `generations` 继续作为视频供应商任务契约，不直接扩展成包含任意文章和图片字段的联合体。实施可选择让 `CreationJob` 引用现有视频 generation，或在兼容迁移后统一任务存储；在 ADR 决定前不得破坏历史读取。

## 能力目录与供应商边界

- 新增平台级文本、图片、视频能力分类；UI 只读取对应分类的可用模型。
- 每个模型声明输入模态、输出模态、支持操作、数量和大小限制、画幅/尺寸、候选数量、同步或异步方式及可计费参数。
- 文本和图片供应商适配器与视频适配器分开，供应商差异仍集中在服务层。
- 普通用户图片能力优先使用受控 API 或审核模板，不能直接获得共享 ComfyUI 队列和任意工作流权限。
- ComfyUI 可作为内部图片或视频执行后端，但必须通过审核模板、平台参数 schema、owner 输出映射、资源预算和任务记录接入。
- API Key 只来自私有 runtime config 或用户明确配置的私有连接，不能进入浏览器日志、公开工作流、作品元数据或错误响应。

## API 行为候选

实施规格至少覆盖下列资源，路径可在开发时调整：

| 资源                                     | 行为                                       |
| ---------------------------------------- | ------------------------------------------ |
| `/api/creative-projects`                 | 项目列表、创建、详情、修改、归档和软删除   |
| `/api/creative-projects/:id/documents`   | 文档与版本列表、保存、恢复                 |
| `/api/creative-projects/:id/storyboards` | 从文章生成或手工创建分镜集合               |
| `/api/storyboards/:id/scenes`            | 场景增删改、排序、版本化                   |
| `/api/creative-assets`                   | 项目作品与素材查询、来源关系和选定状态     |
| `/api/creation/providers?kind=`          | 文本、图片、视频能力目录                   |
| `/api/creation/quote`                    | 按任务类型和请求摘要生成短期报价           |
| `/api/creation/jobs`                     | 幂等受理任务并预留额度                     |
| `/api/creation/jobs/:id`                 | 查询平台状态、结果和结算，不直接轮询供应商 |
| `/api/compositions`                      | 保存编排快照、报价和提交导出               |

所有写接口验证登录、同源、owner 和输入 schema。访问他人资源返回 404；管理员读取和处理遵循现有审计规则。

## 任务状态与用户反馈

平台任务至少统一为以下用户可理解状态：

| 状态        | 用户含义                     | 允许操作                     |
| ----------- | ---------------------------- | ---------------------------- |
| `DRAFT`     | 尚未提交或等待报价           | 编辑、删除、提交             |
| `QUEUED`    | 已预留额度，等待执行         | 查看、符合条件时取消         |
| `RUNNING`   | 供应商或导出 worker 正在处理 | 查看进度                     |
| `SUCCEEDED` | 输出已经生成                 | 预览、保存、继续创作         |
| `FAILED`    | 明确失败                     | 查看受控错误、修改后重新提交 |
| `REVIEW`    | 提交或结算状态不确定         | 等待平台核对，不允许盲目重试 |
| `CANCELED`  | 已确认未继续执行             | 返回编辑或重新提交           |

生成状态、归档状态和结算状态仍分别保存。用户看到“生成成功但归档失败”时可以重试归档，不能把它呈现成模型生成失败。

## 版本、来源与删除规则

- 文章、分镜、提示词、图片编辑和时间线编排均以版本或提交快照参与派生。
- 生成任务提交后输入不可变；“编辑并重试”复制输入形成新草稿。
- 用户可删除未被引用的草稿和候选。已被下游作品引用的内容默认软删除并从普通列表隐藏。
- 删除项目进入回收/归档阶段，不能同步删除正在执行的任务和已结算流水。
- 永久删除前列出受影响资产和导出；法定或账务必须保留的任务元数据继续脱敏保存。
- 封面、缩略图和派生预览可重建，不作为原作品唯一副本。
- 临时供应商 URL 不作为资产身份；成功输出继续归档到私有 OSS。

## 计费与额度

- 文章全文生成、局部改写、分镜生成、图片生成/编辑、视频生成和成片导出均可独立配置价格规则。
- 预览本地编辑、版本切换、选择候选、修改排序和设置关键画面不收费。
- 每次可能产生费用的操作先报价，再由用户提交；自动化链路不得在没有逐步授权或明确总预算的情况下连续提交。
- 多候选输出的报价必须明确包含候选数量。供应商少返回候选时按可验证规则结算或进入核对。
- 重试归档、读取结果和重复查询不重复收费；重新生成和更换模型产生新报价。
- 项目显示累计已结算额度可以作为参考，但每笔流水仍关联具体任务。
- 并发任务、用户预算、平台预算、幂等、未知提交和管理员核对沿用现有生产平台约束。

## 权限与隐私

- 项目、文档、分镜、素材、任务、导出和版本全部保存 owner。
- 首版项目均为私有；公开分享、团队成员和可撤销链接另写规格。
- 供应商请求只携带完成任务所需的选定内容和短期素材授权，不把整个项目无差别发送给模型。
- 提交前界面列出将发送的文章片段、图片、视频和音频引用；用户可移除可选上下文。
- 错误响应、日志和审计不包含 API Key、完整上游响应、签名 URL、文章全文或用户媒体内容。
- 上传、远程素材、内容类型、大小和可访问性限制前后端保持一致。

## 加载、空、失败和恢复状态

- 无项目：展示三个创作入口和最近项目，不显示伪造示例作品。
- 无文章：允许输入想法或粘贴已有正文。
- 无分镜：允许 AI 生成或手工新建。
- 无图片：视频模型支持纯文本时允许继续，否则明确要求参考画面。
- 无视频：时间线显示分镜占位和对应生成操作，不能显示可播放假缩略图。
- 模型不可用：保留用户输入，提示更换模型或稍后重试。
- 余额不足：显示缺口和返回编辑，不清空表单。
- 保存失败：保留本地编辑状态，显示重试；不得显示“已保存”。
- 部分成功：逐候选和逐镜头显示状态，已成功结果可使用，失败部分可单独处理。
- 页面恢复：重新进入项目时打开最后活动阶段并恢复未完成任务状态。

## 边界情况

- 文章正在自动保存时用户生成分镜、切换项目或关闭页面。
- 用户在多个标签页编辑同一文章或分镜；需要版本冲突提示，不能静默最后写入覆盖。
- 文章新版本完成时，旧版本分镜已有图片或视频。
- 删除参考图时存在运行中的视频任务或已完成导出。
- 一次图片任务只返回部分候选、返回尺寸不符或上游标记成功但没有文件。
- 单镜头视频成功而其他镜头失败；用户此时调整分镜顺序并提交导出。
- 导出运行时用户替换时间线镜头；运行任务继续使用提交快照。
- 同一提交在网络超时后再次点击；幂等键只产生一笔预留和一个平台任务。
- 供应商支持的参考图数量、时长或画幅随模型版本变化；旧任务仍按历史快照展示。
- 用户额度足够生成单镜头但不足以生成全部镜头或导出成片。
- 旧视频记录没有项目、封面或来源关系；兼容视图不能伪造不存在的数据。
- 项目包含不同画幅或分辨率的视频；导出前明确裁切、填充或拒绝策略。
- 文本或图片内容被供应商审核拒绝；错误可操作但不回显敏感上游细节。

## 分阶段范围

只分两个可独立交付的阶段。每个阶段内部允许 AI 按数据库、API、页面顺序连续实现，不再为每个模态拆独立里程碑。

### 第一阶段：完整创作闭环

- 建立项目、文章版本、分镜、作品资产和来源关系。
- 实现文章生成与编辑、分镜生成与编辑、普通用户图片生成。
- 将现有视频生成接入项目和分镜，支持图片继续生成视频。
- 作品库按项目统一展示文章、图片和视频，同时兼容旧视频记录。
- 文本、图片和视频统一接入现有报价、额度、后台任务、私有归档和 owner 校验。

完成标准是用户能够独立使用三个模块，也能够完成“文章 → 分镜 → 图片 → 单镜头视频”的端到端流程。

### 第二阶段：短剧成片

- 增加多镜头时间线、当前镜头选择、排序、字幕和基础音频。
- 增加编排快照、异步合成、MP4 私有归档和下载。
- 补充导出报价、失败恢复和成片作品展示。

完成标准是用户能够把第一阶段产生的多个镜头组合并导出一部短剧。

## 验收条件

- [ ] 用户可以分别完成文章、图片和视频创作；首次保存后作品进入本人项目，刷新页面仍可继续。
- [ ] 用户可以完成“文章 → 分镜 → 关键画面 → 单镜头视频”，每个结果保留输入版本、参考素材、模型和参数来源。
- [ ] 修改文章或分镜不会覆盖已经生成的图片和视频；再次生成会创建新结果并重新报价。
- [ ] 模型控件和服务端校验均由能力目录驱动，非法素材、参数和模型组合不能提交。
- [ ] 每个付费生成只产生一个幂等任务和一笔对应的额度处理；候选选择、版本切换和排序不收费。
- [ ] 用户不能读取其他用户的项目、内容版本、素材、任务和下载地址；私有结果通过现有归档与签名链路交付。
- [ ] 旧视频任务继续可查看、播放和结算，并可在用户主动继续创作时关联新项目。
- [ ] 创作台复用现有导航和视觉令牌，文章、图片、视频页面只有一个明确主操作，并覆盖加载、空、成功和失败状态。
- [ ] 第二阶段完成后，用户可组合多个镜头并导出 MP4；导出始终使用提交时快照，编辑中的新变化只影响下一次导出。

## 实现提示

- 在阶段 A 开始前新增 ADR，决定项目、版本、资产关系、统一任务外壳与现有 `generations` 的持久化边界。
- 不建议将现有 `GenerationRequest` 直接改为包含文本、图片、视频所有字段的巨大联合类型；各任务 payload 保持严格、独立和可演进。
- `assets` 继续承担原始文件和私有对象存储身份；`CreativeAsset` 承担作品语义、项目归属和派生关系，避免把文章或场景塞进文件元数据。
- 编辑器的工作草稿与不可变版本应区分，防止每次按键产生数据库版本，同时保证派生任务引用稳定内容。
- 项目聚合查询需要分页和摘要，不能每次打开作品库读取全文、完整工作流图或所有媒体签名 URL。
- 时间线首版应以声明式编排数据为主，合成工作进入独立 worker，不在 Web 请求内调用 ffmpeg 长时间执行。
- 对普通用户开放 ComfyUI 模板前，必须先满足节点白名单、参数 schema、资源预算、owner 文件候选和输出映射，不复用管理员任意画布权限。

## 验证计划

- 每个阶段完成时运行 `pnpm check:full`；涉及队列、额度或限流时再运行 `pnpm test:postgres`。
- 自动化只强制覆盖三类高风险行为：owner 隔离、幂等扣费、版本/来源关系不被覆盖。
- 人工走通一个端到端项目，并检查创作页的加载、空、成功和失败状态。
- 真实供应商、OSS、GPU 或合成只在相应环境可用时验证；未验证项在交付说明中列出。

## 上线与回滚

- 两个阶段分别通过 feature flag 启用；第一阶段创作闭环与第二阶段成片导出可以独立关闭。
- migration 只新增兼容表和可空关联，再逐步回填旧视频项目关系；旧 API 在兼容期继续工作。
- 首先向管理员和内部测试帐号开放，再按用户白名单扩大；观察任务失败率、平均费用、归档失败、长时间预留和存储增长。
- 新模块故障时停止新提交，保留作品读取、历史任务推进、归档与结算 worker。
- 回滚不能删除新项目、版本和流水；旧应用无法识别新数据时采用只读兼容入口或关闭对应导航。
- 第二阶段通过真实合成和下载验收后再开放“导出成片”。

## 待确认的产品决策

- 文章创作首版除故事和短剧故事外，是否同时开放通用文章与营销文案。
- 独立创作首次保存时，是自动创建项目还是先要求用户命名。
- 是否允许用户为一组镜头设置一次总预算并批量确认，还是始终逐镜头确认。
- 首版成片是否包含 AI 配音、背景音乐库和自动字幕，或只使用视频原声与用户上传音频。
- 项目软删除的恢复期限和媒体长期保留策略。
- 图片生成优先接入云 API、审核后的 ComfyUI 模板，或二者同时提供。
- 文本、图片和导出的初始模型、额度售价及对外可用范围。
