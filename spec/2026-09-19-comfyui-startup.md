# 项目启动时自动检查 ComfyUI

- 状态：completed
- 创建日期：2026-09-19

## 背景与问题

本地进程管理器已有探活和启动能力，但 Nuxt 启动没有调用它，管理员每次需要在工作流页面手动启动。

## 目标

- 应用启动自动检查 ComfyUI，已安装的本地实例未运行时自动启动。

## 非目标

- 不自动安装依赖、下载模型、执行工作流或管理远程机器进程。
- 不改变生产 remote 模式边界、数据库或平台契约。

## 用户流程

1. 启动 Nuxt，后台检查 ComfyUI，不阻塞其他页面服务。
2. 已运行则复用；本地已安装且停止则启动并等待就绪。
3. 未安装、远程不可达或启动失败时输出操作提示，管理员仍可在工作流页面安装或重试。

## 行为契约

Nitro 初始化调用现有状态查询和进程管理器。正在启动的实例不重复拉起。启动等待沿用现有超时配置；启动失败被捕获，不输出原始异常或密钥。后台任务只检查一次，用户后续手动停止不会自动重启。构建不执行运行时启动逻辑。

## 验收条件

- [x] 已运行的本地或远程服务不会触发启动。
- [x] 本地已安装未运行时自动调用启动，确认 running 后记录就绪。
- [x] 正在启动的实例不重复启动。
- [x] 未安装、远程不可达、配置错误、启动超时或失败时输出提示，应用仍可服务。
- [x] `pnpm check:full` 通过。

## 边界情况

热重载和手动启动复用现有进程状态；探活期间另一路启动成功创建句柄时，再次检查句柄避免重复生成进程。远程连接失败仍由外部部署负责恢复。

## 验证计划

使用 mock 验证启动分支及失败捕获，执行 `pnpm check:full`。不执行收费生成。

## 上线与回滚

无需新增环境变量或迁移。回滚启动插件即可恢复手动启动流程。

## 实现结果

已增加 Nitro 后台启动检查，复用现有进程管理器并补充探活后的重复启动保护。9 项 mock 测试覆盖运行、停止、启动中、未安装、远程不可达与失败处理。`pnpm check:full` 五项检查通过（54 项测试通过，22 项数据库集成测试按配置跳过）。未执行真实 ComfyUI 冷启动或模型生成；本次不涉及数据库队列或限流变更。
