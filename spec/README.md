# 规格目录

`spec/` 描述“要实现什么”和“怎样算完成”，适合产品功能、修复和跨模块变更。系统当前如何工作写在 `DESIGN.md` 与 `docs/`。

## 使用方式

1. 复制 `_template.md` 为 `YYYY-MM-DD-short-name.md`。
2. 开始实现前将状态设为 `accepted`，明确非目标和验收条件。
3. 实现过程中让代码、测试与规格一起变化。
4. 验收后设为 `completed`，记录与原方案的偏差。

小型、局部且行为不变的维护无需创建规格。涉及共享契约、API 行为、持久化、供应商能力或用户流程的修改应创建规格。

## 状态

- `draft`：仍在讨论，不应据此默认实施。
- `accepted`：可以实现。
- `completed`：已实现且完成验证。
- `superseded`：被另一份规格替代，需链接继任者。
