# ADR-005：创作文档独立于视频生成记录

- 状态：accepted
- 日期：2026-09-17

## 背景

现有 `GenerationRequest`、报价和 `generations` 表具有明确的视频语义。故事和剧本需要长期编辑、版本恢复，以及被人物图、场景图和镜头任务引用。把可变正文加入视频请求会扩大联合类型，并使历史来源不稳定。

## 决策

引入三层创作边界：

1. `creative_projects` 是跨文章、图片与视频的 owner 聚合根。
2. `creative_documents` 保存文档稳定身份和当前版本指针。
3. `creative_document_versions` 保存不可变内容快照、生成连接和输入快照。

文本结构除正文外保留摘要、人物、场景和关键词。后续派生任务引用具体 version ID，不读取可变的“当前正文”。视频 `generations` 保持原契约；未来通过显式项目 / 场景 / 资产关系连接，而不是将文本字段塞进视频请求。

## 后果

- 用户改稿不会改变已经生成的图片或镜头输入。
- 文本、图片和视频可以分阶段迁移而不破坏旧视频记录。
- 当前版本指针是派生查询的便利字段，不替代版本历史事实。
- 增加了项目和版本聚合查询成本；列表必须继续只返回摘要。
- 文本生成在 MVP 中同步执行且暂未计费；开放商业使用前需接入统一任务外壳、报价和 worker。
